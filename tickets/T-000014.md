## Goal
Fix `DocumentExporter.createAttributedString` to use full-text tokenization for both the line-numbers and no-line-numbers code paths. Currently the line-numbers path tokenizes line-by-line, which breaks multi-line constructs (block comments, multi-line strings, heredocs).

## Acceptance Criteria
- [ ] Multi-line strings are correctly highlighted in exported PDF/PNG with line numbers enabled
- [ ] Block comments spanning multiple lines are correctly highlighted in export
- [ ] Exported output matches editor highlighting for the same content
- [ ] Unit test verifies multi-line token highlighting in export

## Notes
File: `qw/Export/DocumentExporter.swift:112-201`
The no-line-numbers path (line 112) already does full-text tokenization. The line-numbers path (line 133) should do the same, then split tokens across lines when inserting line number prefixes.
