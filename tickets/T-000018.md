## Goal
Replace `readableContentTypes = [.item]` in `TextDocument` with a specific list of supported UTTypes. Currently macOS will offer qw as an opener for *any* file type (images, binaries, zip files, etc.) since `.item` is the root type. The app can only handle UTF-8 text files.

## Acceptance Criteria
- [ ] `readableContentTypes` lists specific types: .plainText, .json, .yaml, .html, .javaScript, .pythonScript, .swiftSource, .sourceCode, and UTTypes for .md and .css
- [ ] macOS no longer offers qw as a default opener for non-text files (e.g. .png, .zip)
- [ ] All currently supported file extensions (.txt, .md, .json, .yaml, .yml, .py, .js, .html, .css, .swift) still open correctly
- [ ] Fix `TextDocumentTests.testReadableContentTypes` to assert against actual listed types

## Notes
File: `qw/Models/TextDocument.swift:52-54`
Consider also adding `.sourceCode` as a catch-all for other programming languages while still excluding binary types.
