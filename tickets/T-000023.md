## Goal
Ensure the hex viewer/editor performs well for large binary files (up to 100 MB) by using virtual scrolling and memory-mapped file access.

## Acceptance Criteria
- [ ] Hex view only renders visible rows (virtual scrolling / lazy rendering)
- [ ] Files > 10 MB are accessed via memory-mapped I/O (`mmap` / `Data(contentsOf:options:.mappedIfSafe)`)
- [ ] Opening a 100 MB file in hex mode takes < 500 ms
- [ ] Scrolling through a 100 MB file is smooth (60 fps)
- [ ] Memory usage stays under 50 MB when viewing a 100 MB file (excluding the mmap region)
- [ ] Edits stored as a sparse patch list — not a full copy of file data

## Notes
Use `NSScrollView` with a calculated document height based on total row count (file size / 16). Only read and render the byte range corresponding to the visible scroll region. The `HexDocument` model should abstract over mmap'd source data + edit patches.
