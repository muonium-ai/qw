## Goal
Support text files in the WASM app with syntax highlighting and theme switching while preserving the existing binary viewer flow.

## Acceptance Criteria
- [x] WASM app detects whether the opened file should render in text mode or stay in the existing binary viewer
- [x] Text files render in a dedicated browser text view with syntax highlighting for supported file types and plain-text fallback for unsupported ones
- [x] User can switch themes in the WASM text view and see background/foreground/token colors update without breaking readability
- [x] Binary files continue to open in the current binary/hex viewer without regression
- [x] Static build/dev flow for the WASM app still works, with smoke validation covering at least one text file and one binary file

## Notes
- Existing WASM browser work from `T-000030` and GitHub Pages hosting from `T-000087` are the baseline for this ticket.
- Scope is the browser/WASM experience: add a text mode next to the current binary viewer rather than replacing the binary viewer.
- Reuse native syntax/theme definitions where practical, but prioritize a maintainable browser implementation over perfect code sharing.
- Text/binary routing can use extension hints plus content sniffing; unsupported or very large text files may fall back to plain text if needed for performance.
