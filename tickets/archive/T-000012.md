## Goal
Fix cursor line/column calculation in `MacOSTextEditor.Coordinator.updateCursorPosition` which uses `enumerated()` character indices but compares against `selectedRange.location` (a UTF-16 offset from NSRange). This causes incorrect cursor position display for text containing emoji or non-BMP characters.

## Acceptance Criteria
- [ ] Cursor position is correct when text contains emoji (e.g. "Hello 🌍 World")
- [ ] Cursor position is correct when text contains multi-byte Unicode (e.g. CJK characters)
- [ ] Unit test covers cursor position with non-BMP characters
- [ ] No regression for ASCII-only text

## Notes
File: `qw/Editor/CodeEditorView.swift:623`
The fix should convert the NSRange location to a String.Index using `String.Index(utf16Offset:in:)` or iterate using UTF-16 view instead of character view.
