## Goal
Unskip 5 TextDocumentEncodingTests blocked by FileDocumentWriteConfiguration having no public init on macOS 26

## Acceptance Criteria
- [x] All 5 fileWrapper tests pass (not skipped)
- [x] Text documents produce correct UTF-8 output via fileWrapper
- [x] Binary documents return rawData unchanged via fileWrapper

## Root Cause
`TextDocument.fileWrapper(configuration:)` requires a `FileDocumentWriteConfiguration` parameter, but this type has no public initializer on macOS 26. Tests cannot construct the configuration object to call `fileWrapper()` directly.

## Skipped Tests (in TextDocumentEncodingTests.swift)
1. testFileWrapper_textDocument_createsUTF8Content
2. testFileWrapper_emptyTextDocument_createsEmptyData
3. testFileWrapper_unicodeText_roundtripsCorrectly
4. testFileWrapper_binaryDetected_returnsRawDataUnchanged
5. testFileWrapper_binaryDetected_textModificationDoesNotAffectOutput

## Possible Approaches
- Extract the fileWrapper logic into a separate testable method: `func makeFileWrapper() -> FileWrapper` that doesn't need WriteConfiguration
- Use `fileWrapper(snapshot:configuration:)` if a different overload is available
- Construct WriteConfiguration via Objective-C runtime reflection or unsafe memory layout
- Test via round-trip: write to disk using the document system, read back and verify
- Refactor TextDocument to expose the encoding logic as a pure function

## Notes
File: `qw/qwTests/TextDocumentEncodingTests.swift`. The fileWrapper logic is already tested indirectly via `testFileWrapperLogic_*` tests (3 passing) that verify the encoding paths without calling fileWrapper() itself. This ticket is about getting direct fileWrapper coverage.
